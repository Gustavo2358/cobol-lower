# Índice do conhecimento

O índice é um mapa, não um pacote de contexto obrigatório. Comece pela tarefa e pelo work item.

| Família | Fonte canônica |
| --- | --- |
| Produto, objetivo e cronograma por capacidades | [missão](product/mission-and-slices.md) |
| Repositórios e colaboração paralela | [ecossistema](product/ecosystem.md) |
| Arquitetura e decisões | [índice arquitetural](architecture/index.md) |
| Contratos de tradução | [domínio](domain/index.md) |
| Método de desenvolvimento | [sessão](engineering/agent-session-protocol.md) |
| Pesquisa / regra geral | [política semântica](engineering/semantic-analysis-policy.md) |
| Gates e enforcement | [gates](engineering/gates.md) |
| Oracles e falsificação | [evals](evals/index.md) |
| Próximo trabalho e autorização | [work index](work/index.md) |
| Templates | [templates](templates/README.md) |
| Autoridade, fontes, baselines | [fontes](sources/index.md) |
| Qualidade deste pacote | [relatório documental](quality/harness-validation.md) |

Uma regra durável possui um único endereço canônico. Manifestos, ADRs e catálogos referenciam essa regra; não a duplicam como novas fontes da verdade. Alterar o significado exige o protocolo de mudança, não apenas editar uma tasklist.
