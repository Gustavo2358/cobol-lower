# ADR-0002 — Núcleo independente de transporte e DIP

**Estado:** accepted_by_user_direction. **Data:** 2026-09-06. **Fontes:** Pedido atual; SRC-HANDOFF §21; REF-CLEAN; REF-HEX; ver [registro](../../sources/index.md).

## Contexto

Entrada e saída serão arquivos no desenvolvimento; depois integração Java direta. O núcleo deve permanecer estável.

## Decisão

Porta LowerCobol e input tipado pertencem à aplicação; adapters dependem dessas abstrações. Retornar Publication/resultado não obriga port de persistência. Ports acionados pelo caso de uso expressam necessidades semânticas, não Jackson/Path.

## Consequências

Provar substituição arquivo/memória; gate de imports, assinaturas e bytecode. Mais interfaces não substituem direção correta de dependências.

## Alternativa rejeitada

Escolher o desenho apenas porque é fácil no modelo existente, copiar infraestrutura para o núcleo ou transformar exemplo/limitação de teste em regra semântica.

## Verificação

Os [invariantes](../invariants.md) e [evals](../../evals/catalog.md) operacionalizam a decisão. Enforcement runtime permanece planejado até existir executor e evidência. Mudanças exigem ADR sucessora ou revisão explícita, não edição silenciosa do significado.
